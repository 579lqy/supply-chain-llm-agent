# 操作教程 · supply-chain-llm-agent

本教程手把手带你在本地把项目跑起来、开启「真 LLM」模式、升级向量检索、跑测试，以及部署到 GitHub。
项目位置：`作品集文件夹/supply-chain-llm-agent/`

---

## 0. 先看懂三个模式

| 模式 | 需要什么 | 说明 |
|---|---|---|
| **A. 零依赖演示** | 只装 Python | 走 `rulebased` 后端 + TF-IDF 检索，不调任何 LLM，用来快速看效果、验证链路 |
| **B. 真 LLM** | Python + `openai` 包 + API Key | 用 LLM 做「意图路由 / 抽参 / 答案生成」，真正告别关键词 |
| **C. 向量检索** | Python + `sentence-transformers` 包 | 不调 LLM 也能把检索从「字符匹配」升级为「语义向量召回」，离线可跑 |

> 三种模式可叠加：装了 `sentence-transformers` 后再开 LLM，就是「真 LLM + 向量检索」全状态。

## 3. 模式 B：开启真 LLM（核心升级）

### 3.1 装包
```bash
pip install openai
```
（用托管 Python 的话：`路径\python.exe -m pip install openai`）

### 3.2 拿一个 OpenAI 兼容的 Key
本项目用 **OpenAI 兼容接口**，所以下列任一家的 Key 都能用，只换 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`：
- OpenAI 官方：`https://api.openai.com/v1`，模型 `gpt-4o-mini`
- DeepSeek：`https://api.deepseek.com/v1`，模型 `deepseek-chat`
- 通义千问：`https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen-plus`
- 智谱 GLM：`https://open.bigmodel.cn/api/paas/v4`，模型 `glm-4-flash`
- 本地 Ollama：`http://localhost:11434/v1`，模型 `qwen2.5:7b`（需先 `ollama serve`）

### 3.3 设环境变量并运行

**命令提示符（cmd）写法：**
```bash
set LLM_BACKEND=openai
set OPENAI_API_KEY=sk-你的key
set OPENAI_BASE_URL=https://api.openai.com/v1
set OPENAI_MODEL=gpt-4o-mini
python src\demo.py
```

**PowerShell 写法（注意语法不同）：**
```powershell
$env:LLM_BACKEND="openai"
$env:OPENAI_API_KEY="sk-你的key"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
$env:OPENAI_MODEL="gpt-4o-mini"
python src\demo.py
```

跑起来后，控制台第一行的 `[后端]` 会变成 `openai`，答案就是 LLM 实时生成的了。

### 3.4 想自定义问法？
编辑 `src/demo.py` 第 26 行：
```python
DEMO_QUERY = "把你的问题写这里，例如：上海仓安全库存低于 7 天的 SKU 有哪些？"
```
保存后重新 `python src\demo.py`。

也可以写一个自己的小脚本调用（和 demo 同目录即可）：
```python
from rag_agent import LlmRagAgent, format_answer
agent = LlmRagAgent()
print(format_answer(agent.run("深圳仓缺陷率最高的 3 个 SKU 是谁？")))
```

> 没有 Key 时 LLM 某一环节失败会自动回退到规则逻辑，不会直接报错崩掉。

## 4. 模式 C：升级向量检索（无需 Key）

```bash
pip install sentence-transformers
python src\demo.py
```
首次运行会自动下载 `bge-small-zh-v1.5` 模型（约几百 MB，需联网）。之后检索从 TF-IDF 字符匹配变成**语义向量召回**，对同义问法更鲁棒。

可以在代码里看当前用的是哪种检索器：`src/vector_retriever.py` 的 `get_retriever()` 会按可用性自动选 `vector → tfidf`。

## 5. 跑测试 / 评测

```bash
python tests\run_tests.py
```
默认 `LLM_BACKEND=rulebased` 时，会跑：
- 10 个单元测试（manifest 转换、工具执行、答案契约等）
- 21 条人工标注评测，输出 **意图准确率 / Recall@3 / 端到端准确率**

开启 LLM 后评测会额外输出：**工具调用准确率、忠实度（防幻觉）、单次成本与时延**。
```bash
set LLM_BACKEND=openai
set OPENAI_API_KEY=sk-你的key
set OPENAI_BASE_URL=https://api.openai.com/v1
set OPENAI_MODEL=gpt-4o-mini
python tests\run_tests.py
```

## 6. 换成你自己的数据 / 知识

- **真实业务数据**：替换 `data/real_supply_chain.csv`（列保持 `sku, location, on_hand, safety_stock, lead_time_days, defect_rate, daily_demand, avg_cost` 等，参考现有文件表头）。
- **知识库（SOP / 公式）**：编辑 `knowledge_base/` 下的 `.md`，新增文件也会被 `chunker` 自动切片进检索。
- **新增工具（让 LLM 能调用更多能力）**：在 `src/mcp_tools.py` 里加函数，并补到 `tool_manifest()`，LLM 会自动获得调用权限（无需改路由代码）。

## 7. 部署到 GitHub（公开仓库）

项目已在本地 `git init` 并提交，但**还没推到 GitHub**。需要你提供一个有写权限的 PAT（Personal Access Token）：

1. 去 GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)**
2. 生成 `ghp_` 开头的 token，勾选 **repo** 权限，有效期建议 7 天。
3. 把 token 发给我，我来建仓 `supply-chain-llm-agent` 并推送。
4. 推送完**立即去 GitHub 撤销该 token**（避免长期暴露）。

> 安全提醒：之前几个 classic PAT 都还在有效期内，建议统一去 GitHub 撤销掉，换成每次短期新 token。

## 8. 常见问题

**Q：报 `ModuleNotFoundError: No module named 'openai'`？**
A：没装包或装错环境。确认 `pip install openai` 时用的 Python 和跑 `python src/demo.py` 的是同一个。

**Q：开了 LLM 但答案还是像关键词版？**
A：检查 `OPENAI_API_KEY` 是否设上（同窗口、同 shell）。`[后端]` 显示 `openai` 才代表真在调 LLM。PowerShell 和 cmd 的环境变量不互通，重开窗口要重设。

**Q：本地 Ollama 连不上？**
A：先 `ollama serve`，确认 `http://localhost:11434/v1` 能访问，模型名用 `ollama list` 看到的名字。

**Q：想换成本地模型不联网？**
A：装 `pip install sentence-transformers` 升级检索（离线），LLM 部分用 Ollama 本地模型即可全离线。

**Q：评测里的「忠实度」是什么？**
A：检查 LLM 答案里的「结论/策略/风险」是否真能从召回的知识 + 工具返回的数据里找到依据，找不到算幻觉，用于约束模型不乱编。
